# v2.1.6 第三轮性能优化

记录日期：2026-10-06，北京时间。基线为第二轮 2.1.6 测试构建的源码快照，结果对应本轮最终工作区。测试浏览器为 Chromium 151.0.7922.34。

## 实现

- 对末端复合选择器的必要条件统计出现频率，优先使用较少出现的条件筛选字体规则；同等频率按 ID、类名、标签选择。逗号列表的每个分支都要具备可靠条件，完整命中继续由浏览器判断。
- 小分支的字体变化、移动和移除只清除对应继承上下文，保留其他区域的缓存；清理最多遍历 128 个已缓存后代，整页及大分支变化直接重建上下文。
- 同批字符写入按文字节点去重，纯文字节点替换按父级合并最终检查。非空判断直接查找非空白字符，减少长文本尾部空白造成的扫描；保留字体属性、关系条件、首次文字和实际方向变化的判断。
- 在每批增量扫描中复用共同祖先的覆盖结果，减少深层区域兄弟节点反复遍历到文档根部；父子同时变化时由最外层扫描覆盖。
- 存储更新后比较当前页面的实际配置，其他站点规则、目标名单顺序及相同 CSS 的新分块代次不触发整页重扫。仍更新分块引用，正文或生效配置改变时完整重检；保留未完成的输入、播放和字体加载任务。
- 同批兄弟元素共享代码、图形保护与自动方向的祖先查询，每个自动方向根只检查一次实际方向。缓存限定在本批内，自身标签、图标字体与类名继续单独判断。

用户 CSS 正文和 Apple UI Mix 模板保持原样。源码快照保存时统一了换行，因此基线 CSS 的原始字节摘要不同；将 CRLF 统一为 LF 后，基线与工作区的 CSS 文本完全相同。工作区 `shared.js` 和 `apple-ui-mix.css` 与 Git 中的原文件一致。

## 测试范围

90 项自动回归通过，覆盖真实 MV3、隔离脚本、跨域 CSS、子框架、输入与组词、拖选、视频调度、保护、连字、站点 CSS、配置竞态及安装包加载。

内容脚本测量扩展为 34 类独立模拟场景，包含首次加载、百万字符长文本、大型/深层 DOM、字体规则与变量、批量新增/移动、菜单、小分支缓存、深层兄弟变更、保护区域、复杂条件、Unicode 空白与关系字体、自动方向、组词与失焦、媒体条件、键盘输入、鼠标拖选、原生视频、播放中的节点移除、站点动作与保护/连字切换、禁用重启及实际配置不变的存储更新。

普通替换和完整 Apple UI Mix 两种模式均比较无扩展、改动前和改动后。关闭高频选择器/遍历计数的计时覆盖全部 34 类，每组交替顺序重复 3 次，共 612 个样本；另对全部场景运行一次调用量复核，共 204 个样本。组词使用合成事件，输入和拖选使用独立测试浏览器的键盘及鼠标操作。所有场景检查最终状态，完整样本与范围保存在 JSON 中。

## 重复测量结果

下表为 3 次测量的中位数，单位为 ms。主线程指标包含解析、脚本、样式和布局；脚本指标为 CDP 的 ScriptDuration。耗时包含模拟页面和保留的测量钩子开销。

| 场景 | 指标 | 普通替换，前 → 后 | 完整 CSS，前 → 后 |
|---|---|---:|---:|
| 800 条通用标签/类名前缀规则，1600 个元素 | 主线程 | 714.26 → 78.43 | 874.21 → 225.50 |
| 百万字符尾部空白文本，800 次同批写入/替换 | 脚本 | 209.77 → 2.95 | 212.48 → 3.00 |
| 小分支字体切换与 100 层主分支菜单更新 | 脚本 | 212.19 → 14.96 | 213.00 → 13.87 |
| 500 层共同祖先下，300 个兄弟反复切换字体 | 脚本 | 47.36 → 19.58 | 71.28 → 20.97 |
| 6000 段文字，8 次其他站点规则与相同 CSS 分块更新 | 主线程 | 324.64 → 17.45 | 916.97 → 17.76 |
| 同一配置更新场景 | 样式重算 | 44.64 → 0 | 402.09 → 0 |
| 复杂字体条件，6400 次完整采样 | 脚本 | 16.01 → 13.85 | 16.84 → 13.58 |

百万字符密集更新的脚本耗时范围为：普通替换 206.30～213.30 → 2.86～3.24 ms，完整 CSS 210.58～213.05 → 2.91～3.18 ms。该场景保留 4 批共 800 次写入，文字包含百万字符的尾部空白，属于长文本压力用例。

普通替换的通用前缀规则场景，最长主线程长任务中位数由 660 ms 降至 0；完整 CSS 模式由 664 ms 降至 181 ms。实际配置不变的场景，两种模式均从 8 次采样和 8 次样式表停用降为零，标记写入由 80000 次降为零。

最终调用量复核中，通用前缀规则的 `Element.matches` 调用由普通替换的 1280808 次降至 2408 次，完整 CSS 的 1280810 次降至 2410 次；两版仍各采样 800 次。小分支与深层菜单场景由 636084 次匹配降至 18084 次，两版仍各采样 2 次。两份报告均覆盖 68 个模式/场景组合，无页面脚本错误，改动后源码摘要与最终文件一致。

新增回归用例验证：800 次长文本写入只读取 4 次最终文本；500 层兄弟变更只读取 1404 次父级；300 个兄弟的保护/方向查询为 7 次，实际方向检查为 2 次。移动到代码区域、关闭保护、Unicode 空白、关系字体与方向切换均完成最终判断。

## 基本持平及略高的结果

- 百万字符首次加载：普通替换的主线程中位数为 194.14 → 194.24 ms；完整 CSS 为 536.64 → 535.51 ms，其中布局为 299.57 → 298.56 ms、样式为 165.11 → 165.80 ms。主要开销仍是浏览器排版。
- 6000 段文字及 100 个空控件的完整 CSS 首次加载：主线程 467.59 → 468.25 ms，脚本 31.09 → 28.95 ms，样式 259.14 → 262.07 ms。
- 完整 CSS 的视频持续更新：主线程 59.56 → 62.92 ms，布局 24.48 → 28.39 ms，脚本 4.97 → 5.57 ms；采样数量及最终字体判断保持一致。
- 完整 CSS 的 128 个独立字体属性变更：主线程 77.10 → 78.12 ms；两版均保持 2 次样式表停用。普通替换的输入与拖选主线程分别为 70.04 → 69.31 ms、31.00 → 31.36 ms。

各场景的最小值、最大值及逐样本指标见完整 JSON。完成时间含场景操作与调度；首次加载的完成时间还含测量工具的稳定等待，主要对比使用主线程和脚本指标。堆内存受垃圾回收影响，帧间隔来自独立测试浏览器。这些结果描述本地模拟页面。
