# v2.1.6 性能测试与优化记录（第一轮）

第二轮结果见[继续优化记录](round2-summary.md)。

基线为 v2.1.5，测试浏览器为 Chromium 151.0.7922.34。完成内容脚本、后台读取和设置页的一轮全面优化。用户 CSS 正文与 Apple UI Mix 模板保持原样。

## 测试范围与方法

- 20 类内容脚本场景，普通替换和完整 Apple UI Mix 两种模式；每组比较无扩展、v2.1.5 与工作区，各重复 3 次，共 360 个样本。
- 覆盖首次加载、6000 段文字、250 层继承、800 条字体规则、24 层变量依赖、无文字结构、批量增删与移动、字体属性、样式表、保护区域、复杂条件、菜单、输入、拖选、视频与配置重载。
- 另对 7 类关键场景关闭高频选择器/遍历计数钩子，完成 126 个计时复核样本。下表内容脚本耗时使用此轮复核的中位数。
- 设置页分别测量 100/400 条规则的加载、编辑与 CSS 分块保存，使用测试存储环境；每组交替执行前后版本，各重复 3 次。
- 79 项自动回归全部通过，包括真实 MV3、跨域 CSS、子框架、输入法、拖选、保护、媒体条件、缓存容量、站点 CSS、菜单、屏外条目与 ZIP 安装包校验。

浏览器耗时包含本地模拟页面及保留的采样/标记钩子开销。主线程任务包含解析、脚本、样式及布局；帧间隔来自测试浏览器的 requestAnimationFrame。堆内存为采样值，受垃圾回收影响。原始样本保存最小值、最大值和源码摘要。

| 800 条字体规则，完整 CSS，主线程任务 | 532.83 ms | 232.59 ms |

操作次数来自完整计数轮。编辑与保存的主线程任务包含浏览器布局和交互；纯脚本回调耗时从 14.17 ms 降至 10.57 ms。

## 实现变化

字体规则按类名、ID 和标签查找候选，简单类名/ID 直接匹配；复杂规则和怪异模式继续交给浏览器判断。继承路径改为迭代计算和编号复用，编号来源上限为 4096，字体快照上限仍为 1024。媒体条件每批计算一次，字体变量依赖使用图遍历。

主要内容的大批兄弟节点共享收集与资源查询，文字叶子直接处理。补齐初次整页扫描的空控件，并检测字体属性、控件类型、媒体条件、视口下的容器条件及关系选择器变化。

跨域 CSS 请求最多并发 32 个，读取和等待请求总量最多为 128；5 秒预算包含等待时间。设置页规则在文档片段中初始化，复用字段引用，屏外规则延后排版；聚焦、键盘菜单、CSS 草稿及返回滚动位置均有回归覆盖。

## 当前耗时重点

完整 CSS 在极端长页面首次应用时，浏览器样式与字体排版仍占较多时间。6000 段文字加 100 个空控件的场景，主线程中位数为 413.00 → 493.75 ms，其中样式重算为 186.41 → 270.11 ms。新版为此前漏检的空控件建立替换标记，这组结果包含新增的正确处理成本。6000 段纯文字的同轮结果为 414.71 → 417.33 ms。

复杂字体条件继续完整采样。容器条件压力场景中，两版均执行 6400 次原样式采样；完整 CSS 的主线程耗时为 286.62 → 289.13 ms。字体、保护和方向变化仍按实际原样式判断。
